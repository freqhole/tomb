each node owns its music + video metadata. spume keeps a separate browser
cache. these three diagrams are generated from the current SQL migrations,
registered query views, and the actual fresh-install IndexedDB upgrade functions.
regenerate them with `npm --prefix freqhole.net run gen:schema`.

drag to pan, use the + / - buttons to zoom, or use the mouse wheel over a focused
diagram. click a node to center and zoom to it (or focus it and press enter).
the selected node and its connected edges turn magenta. click the same node again
to fit it and its directly connected neighbors; further clicks alternate between
the node alone and that neighborhood.
click the background or press Escape to back out three zoom steps for surrounding
context; this happens once per focused node, not on every background click.
**fit** resets the view. the graph remains interactive on touchscreens.

## on a node: SQLite

the table graph includes grimoire metadata, haruspex identities/access grants,
and reliquary blob metadata. these are separate SQLite files, identified by each
table's prefix. media bytes live outside these metadata databases. legacy tables
remain visible until a migration actually drops them.

relationships are real foreign keys, not guessed from column names. primary keys
are marked `PK`, foreign keys `FK`. FTS virtual/shadow tables are omitted.

## query views

the registered views are recreated after migrations in dependency order. this
graph reads **source tables → stored SELECT → output fields**, with a panel for
each view and wires for upstream view dependencies. blue nodes list table inputs,
purple nodes are views, and green nodes show every actual output column, grouped
by entity prefix. amber nodes show example caller filters/sort/pagination using
current column names (illustrative SQL, not an exhaustive API contract).
this includes the internal library-availability views.

views do not take parameters. repository callers apply filters (`WHERE`), sorting
(`ORDER BY`) and pagination (`LIMIT` / `OFFSET`) around the stored SELECT, then
map the projected rows into API models. these are caller operations, not extra
view columns. the sources and output fields below are generated from SQLite,
not a hand-maintained sketch of an older API contract.

## in the browser: IndexedDB

the graph combines app state, the music catalog, the video catalog, and reliquary's
blob metadata database. each store lists its key and indexes; `UK` means a unique
index. dashed wires show **application-level references**, including conditional
links selected by `entity_type` / `target_type`. these are not enforced foreign
keys or uniqueness guarantees; a referenced cached record can be absent.
playlist song references use `sha256`, while import-review song references use
the local `id`—they are not interchangeable.

keys/indexes are introspected; reference meanings are checked against the
record types and lookup code, with endpoint fields validated during generation.
snapshot/history stores deliberately remain unconnected when they embed records
rather than join another store. raw browser media lives in OPFS or the Cache API,
not these stores.
