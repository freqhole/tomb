## updating

- **desktop app:** choose **freqhole → check for updates**, then follow the release link to download and install your platform's update. some updates need an extra restart.
- **CLI:** download the new binary, replace the old one, and restart the server.

database migrations run automatically on startup.

## maintenance reference

the core operations below are available in **charnel, rathole, and the CLI**.
they call shared grimoire logic; controls and execution differ:

- **charnel:** open **Library → maintenance**, recheck counts, select tasks, and run them. reference audit, asset repair, and file reorganization have separate panels.
- **rathole:** choose an action from the **admin command palette**. `/maintenance help` lists slash-command shortcuts.
- **CLI:** prefix the command below with `freqhole`. use `<group> <command> --help` for options.

| operation                   | what it does                                                                                                | CLI command                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| orphaned tags               | removes tags with no references.                                                                            | `maintenance cleanup-orphaned-tags`                |
| orphaned genres             | removes genres with no references.                                                                          | `maintenance cleanup-orphaned-genres`              |
| orphaned artists            | removes artists with no music or video references.                                                          | `maintenance cleanup-orphaned-artists`             |
| orphaned albums             | removes albums with no music or video references.                                                           | `maintenance cleanup-orphaned-albums`              |
| orphaned video series       | removes series with no videos.                                                                              | `maintenance cleanup-orphaned-video-series`        |
| orphaned taxons             | removes unreferenced non-genre taxons.                                                                      | `maintenance cleanup-orphaned-taxons`              |
| orphaned blobs              | reclaims unreferenced blob storage; scanned files outside `data_dir` are left untouched.                    | `music cleanup-orphaned-blobs`                     |
| contentless blob records    | removes records with no retrievable content.                                                                | `maintenance cleanup-contentless-blobs`            |
| old music records           | permanently removes old soft-deleted music records.                                                         | `music hard-delete-old-records`                    |
| old video records           | permanently removes old soft-deleted video records.                                                         | `video hard-delete-old-records`                    |
| missing content hashes      | calculates missing BLAKE3 hashes.                                                                           | `blobz backfill-blake3`                            |
| P2P-store backfill          | registers already-hashed media in transport storage.                                                        | `maintenance backfill-fsstore`                     |
| missing image thumbnails    | generates missing image-thumbnail sizes.                                                                    | `maintenance backfill-thumbnails`                  |
| library asset repair        | fills missing waveforms, album art, and video posters.                                                      | `maintenance repair-library`                       |
| waveform repair             | fills missing song and video waveforms only.                                                                | `maintenance repair-library-waveforms`             |
| album-art repair            | fills missing album art; optional `--remove-overapplied` removes over-applied directory art.                | `maintenance repair-library-thumbnails`            |
| missing video posters       | extracts posters only for videos that lack them.                                                            | `maintenance repair-library-video-thumbnails`      |
| regenerate video posters    | replaces existing video posters.                                                                            | `maintenance regenerate-video-thumbnails`          |
| re-transcode videos         | queues replacement renditions for videos that already have them; optional `--video-id ID` limits the scope. | `maintenance retranscode-video-renditions`         |
| blob-reference audit/repair | checks known P2P file references; `--repair` registers verified paths without moving or deleting media.     | `config storage audit-references`                  |
| reorganize fetched files    | previews or moves fetched music/video into a chosen layout.                                                 | `maintenance reorganize-library --target-dir PATH` |

### previews, defaults, and variations

- **preview first:** cleanup, asset-repair, poster-regeneration, P2P-store-backfill, and reorganization commands support `--dry-run`. in charnel, use counts/previews before running destructive work.
- **30-day defaults:** orphan-blob cleanup measures age from **blob creation**; record retention measures age from **soft deletion**. CLI overrides are `--min-age-days N` and `--retention-days N`. explicit values in scripts still take precedence.
- **charnel groups metadata cleanup:** one checkbox runs the six metadata-cleanup operations. metadata cleanup and missing image thumbnails start checked; other maintenance tasks start unchecked.
- **asset repair:** charnel rescans tracked directories before the selected repairs. CLI/rathole asset-repair actions do not add that rescan. use the repair options to choose waveforms, embedded/directory album art, video posters, and optional removal of over-applied art.
- **execution:** most cleanup/backfill actions return a summary. video transcodes use queued jobs. charnel/rathole also queue reference audits and reorganization batches; CLI audit/reorganization run directly. worker-dispatched library-image repairs use queued batches.

:::caution[rescanning and retention]
rescanning can import, relocate, restore, or soft-delete song records as files appear or disappear. hard deletion is permanent. review the selected scope and back up first.
:::

### additional tools

these are diagnostics, shortcuts, or installation-specific actions rather than separate core maintenance operations:

- `freqhole database info` and `freqhole database test` check the main database.
- `freqhole music check-blob-references --blob-id ID` shows a blob's library references.
- `freqhole blobz blake3-status` reports hash-backfill status; charnel shows the count in maintenance previews.
- `freqhole maintenance cleanup-all` combines **tags and genres only**. charnel's metadata checkbox covers more entities.
- `freqhole music run-maintenance` combines music-record retention and orphaned-blob cleanup; rathole calls this **full maintenance**. charnel offers those tasks separately.
- `freqhole maintenance update-server-image` refreshes the configured server image. charnel has server-image controls in settings; rathole offers `/maintenance update-image`.
- `freqhole maintenance update-spume` refreshes embedded web-client files for an HTTP-server installation with static files configured; rathole offers `/maintenance update-spume`. charnel doesn't serve this HTTP web client.

## storage references and cleanup

reference repair restores P2P availability; it does **not** reclaim disk space.
it verifies recorded files against their expected hashes, then registers valid paths:

```bash
freqhole --config /path/freqhole-config.toml config storage audit-references
# stop other freqhole apps before repairing the transport index:
freqhole --config /path/freqhole-config.toml config storage audit-references --repair
```

in charnel, use **Library → audit and repair blob references**. in rathole:

```text
/maintenance audit-references
/maintenance audit-references repair
```

reconnect missing disks or correct known paths first. repair cannot find files moved to an unknown location.

the P2P node runs periodic iroh-blobs garbage collection, reclaiming entire hashes once blob metadata no longer protects them. it does not prune one stale external path while its hash remains protected. do not edit or delete `freqhole-blobz/blobs.db`.

## out of disk space

1. pause imports, scans, and other writers. first free space **outside** the active data set — for example, move known old backups to another disk. don't manually delete blob-store files or SQLite databases!
2. with some free space available, preview orphan-blob cleanup:

   ```bash
   freqhole music cleanup-orphaned-blobs --dry-run
   ```

3. review the summary, then run without `--dry-run`. the default minimum age is **30 days**. to include newer orphaned blobs, preview the broader scope first:

   ```bash
   freqhole music cleanup-orphaned-blobs
   freqhole music cleanup-orphaned-blobs --min-age-days 0 --dry-run
   # only after reviewing the preview:
   freqhole music cleanup-orphaned-blobs --min-age-days 0
   ```

4. if old soft-deleted records also need purging, preview then apply:

   ```bash
   freqhole music hard-delete-old-records --dry-run
   freqhole video hard-delete-old-records --dry-run
   # only after reviewing the previews:
   freqhole music hard-delete-old-records
   freqhole video hard-delete-old-records
   ```

   run orphan-blob cleanup again afterward: record deletion can create new orphans.

5. check free space with your operating system and database size with `freqhole database info`. if capacity is still insufficient, add space or follow the [storage-folder change guide](/concepts/storage/#changing-storage-folders).

reference audit/repair isn't a disk-cleanup tool. see [where media lives](/concepts/storage/) for storage ownership and backup details.

## backup

stop all freqhole apps before copying database and storage files so SQLite WAL
and blob stores remain consistent. replace `data/` with your configured path.

### database

```bash
cd /path/to/your/freqhole-install/
sqlite3 data/grimoire.db ".backup data/grimoire-backup.db"
```

### complete data backup

```bash
cd /path/to/your/freqhole-install/
tar -czf freqhole-backup.tar.gz data/
```

include the entire configured data directory, including SQLite databases,
`blob-files/`, and `freqhole-blobz/`. separately configured database/fetch
folders and original scanned media need backing up too. see [storage and backups](/concepts/storage/#backing-up).

to restore, stop all apps, restore the data to its expected paths, then restart.

## logs and troubleshooting

logs go to stderr for the CLI and the application logs directory for charnel.
set verbosity with `RUST_LOG`:

```bash
RUST_LOG=debug freqhole serve
```

- **server won't start:** check the config, writable data directory, and any configured HTTP port. use debug logs for details.
- **database locked:** stop other apps or external tools using the same database before retrying.
- **P2P connection fails:** check connectivity and relay configuration, then see [HTTP vs P2P](/concepts/transports/). port forwarding is not normally required.
