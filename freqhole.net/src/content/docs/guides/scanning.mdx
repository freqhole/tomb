freqhole scans directories to import music + video files into your library. discovery is shared, then each file goes through its domain-specific import pipeline.

## configuring scan directories

scan directories are passed to the scan command or selected in the desktop app — there's no config file section for them. supported formats are configured in `[media].supported_audio_formats` and `[media].supported_video_formats`.

### in desktop app

settings → library → add folder

choose **music** or **video** for the folder. the desktop command defaults to music when no domain is supplied so older callers keep their existing behavior.

---

## running a scan

### CLI

```bash
freqhole music scan --path ~/Music
```

despite the legacy `music scan` command name, this CLI path currently scans for both configured audio and video formats.

rescan all previously tracked directories:

```bash
freqhole music scan rescan
```

### desktop app

library → scan now

### web app

settings → library → scan (member/admin only)

## what happens during scan

1. **discover files**: find configured audio and/or video formats in the directory
2. **deduplicate**: skip files already tracked at the same path
3. **queue imports**: create background jobs for new files
4. **extract metadata**: read music tags or probe video properties
5. **extract images**: pull embedded cover art or generate a video poster
6. **create entities**: songs link to albums + artists; videos enter the video library
7. **index for search**: make imported media available to library queries

## music metadata extraction

### supported tags

- title, artist, album artist
- album, track number, disc number
- year, genre
- duration, bitrate, sample rate

### embedded artwork

cover art is extracted from:

- ID3 APIC frames (MP3)
- Vorbis METADATA_BLOCK_PICTURE (FLAC/OGG)
- MP4 covr atom (M4A)

stored as blobs, deduplicated by content hash.

## video metadata extraction

video imports use `ffprobe` to inspect the container and streams. freqhole records properties including:

- duration
- width + height
- video + audio codecs
- container format
- embedded subtitle streams

the filename becomes the initial title for a scanned video. you can edit its title, content type, series, season, episode, and other library metadata after import.

### generated posters

freqhole uses `ffmpeg` to extract a representative frame as the initial video poster. poster extraction is best-effort: a video can still import if no poster can be generated.

### renditions

when video transcoding is enabled, follow-up jobs can create configured playback renditions. the original file remains the source and is not modified.

## file formats

defaults are shown below; both lists are configurable.

### music

| format     | extension | notes             |
| ---------- | --------- | ----------------- |
| MP3        | .mp3      | ID3v2 tags        |
| FLAC       | .flac     | Vorbis comments   |
| Ogg Vorbis | .ogg      | Vorbis comments   |
| AAC        | .m4a      | iTunes-style tags |
| WAV        | .wav      | limited metadata  |
| Opus       | .opus     | Vorbis comments   |

### video

| format    | extension | notes                      |
| --------- | --------- | -------------------------- |
| MPEG-4    | .mp4      | common browser playback    |
| Matroska  | .mkv      | may require a rendition    |
| WebM      | .webm     | browser-friendly container |
| QuickTime | .mov      | probed with ffprobe        |
| AVI       | .avi      | may require a rendition    |

## handling duplicates

freqhole tracks media files by path. if the same file is moved:

- old path: shows as missing
- new path: imports as new song

to clean up missing files:

```bash
freqhole maintenance cleanup-orphans
```

---

## incremental vs full scan

### incremental (default)

- only processes new files (not in database)
- fast for adding new media
- does not update changed tags

### rescan

```bash
freqhole music scan rescan
```

- reprocesses all previously tracked directories
- slower but ensures everything is up to date

## troubleshooting

### files not appearing

check:

1. file extension in the matching `[media].supported_audio_formats` or `[media].supported_video_formats` list?
2. file readable by the freqhole process?
3. valid media file (not corrupted)?

### wrong music metadata

tags embedded in the file take priority. to fix:

1. update tags in the file (with Mp3tag, Picard, etc.)
2. run `freqhole music scan rescan`

or edit in the web app (overrides file tags).

### wrong video metadata or missing poster

check that `ffprobe` and `ffmpeg` are installed and that their paths are configured correctly. scanned filenames provide only an initial title; edit video, series, and season metadata in the app after import.

### scan is slow

normal for large libraries on first scan. subsequent scans are incremental.

tips:

- exclude non-media directories
- use SSD for database
- reduce extensions list
