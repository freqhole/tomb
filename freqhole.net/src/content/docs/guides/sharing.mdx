share your music + video library over P2P without port forwarding. first, choose what you want to do:

- **let a friend browse your library:** invite them or approve their access request.
- **control another device's playback:** [pair a player](#pair-a-player) using its QR code and PIN.
- **send an album, video, or playlist:** use that item's **share** button. the recipient still needs access to its source library.

:::note[address vs permission]
a node ID, library link, or library QR code tells someone **where to connect**. an invite code or approved knock grants **library access**. a player PIN grants **player control** — these are different permissions.
:::

## share from charnel

use the local wizard's admin views:

1. open **federation**, enable it if needed, and copy your **node ID**.
2. send your friend this link, replacing `NODE_ID` with your own:

   ```text
   https://spume.freqhole.net/?r=NODE_ID
   ```

3. choose one way to grant access:
   - **invite:** open **users → invitez → generate invite**, check the invite's role, and send the code privately.
   - **knock:** with knocking enabled, your friend requests access when connecting. review it under **federation → access requests**, then approve or deny it.

choose **viewer** for someone who should only browse and play media. use a higher role only when you want them to edit or administer your library.

already know your friend's device node ID? **federation → allowed peers** lets you associate it with a user directly, instead of exchanging an invite.

## share from rathole

use these commands inside the terminal app:

| task                           | command                            |
| ------------------------------ | ---------------------------------- |
| find your node ID              | `/info`                            |
| copy a browser connection link | `/copy-invite`                     |
| generate an invite code        | `/invite create`                   |
| review pending access requests | `/knock list`                      |
| approve or deny a request      | `/knock accept` or `/knock reject` |
| revoke an unused invite        | `/invite revoke`                   |

the invite and knock actions open forms where you choose the details. `/copy-invite` copies a connection link, **not** an access code.

for command-line peer approval outside the TUI:

```bash
freqhole federation allow-peer FRIEND_NODE_ID --username friend --role viewer
```

## connect from charnel or the web app

the library interface uses the same flow on desktop, mobile, and in a browser:

1. open **add remote**.
2. paste the library's node ID or connection link, or scan its QR code when a camera is available.
3. redeem the invite code and follow the account prompts. without a code, submit a knock if the library allows requests.
4. once access is granted, select the remote to browse and play its media.

your friend can send the address through any trusted side channel — a message, email, or printed QR code. scanning saves typing; it doesn't bypass approval.

already have an account and want to add another device? use an **account-link code**, rather than creating another user. see [invite codes](/concepts/invite-codes/).

## pair a player

this is for playing **on another device**, not browsing its library:

1. open the destination device's **player** screen. in rathole, use `/player`.
2. on your controller, open **add remote** and scan the player's QR code, or paste its node ID.
3. enter the PIN shown on the player when prompted.
4. select the paired player as your playback target, then queue media.

if charnel offers **allow this player to access your library**, leave it enabled when the player needs to fetch media from you. pairing alone doesn't grant that library access.

see [cenotaph](/guides/cenotaph/) for player modes, trusted controllers, and admin pairing.

## access and privacy

- **viewer** access lets friends browse and play media, not edit your library.
- activity feeds can show playback sessions, favorites, and ratings; don't assume playback history is private.
- share invite/account-link codes and player PINs only with the intended person. check the role before approving.
- revoke unused invites or remove a device's allowed-peer access in the admin views when needed. revoking an unused invite doesn't remove an account that already redeemed it.

P2P connections are encrypted; a relay carries traffic when a direct connection isn't available. see [HTTP vs P2P](/concepts/transports/) for transport details.
